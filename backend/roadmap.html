Launch Scope Day one: what a new user does

The core loop for someone opening the app for the first time. Everything here needs to work end-to-end before launch. Features outside this loop are post-launch iteration.

Open app → Sign up / log in → Answer questionnaire → Get workout → Log sets → See recap + progression
Already works
  • Open app → login screen
  • Email signup + login
  • Questionnaire: 12 sections, one screen each, single/multi-select
  • Generate workout from answers → save as draft → start
  • Log sets during workout: weight, reps, effort (1–10)
  • Complete workout → see recap screen
  • View past workouts in history
  • AI Coach tab: ask questions, request workout changes
Needs verification
  • Weight units: verify consistent — start_weight seeded in lbs, frontend assumed kg. Fix applied; needs a real workout to confirm numbers display correctly end-to-end.
  • Coach Recap on Ready screen — session lookup returns empty even when completed session exists. Needs testing with a real completed session.
  • Progression visible to user — backend now computes next prescription and increases weight (5 lb on first set). Confirm the UI surfaces that change where the user expects to see it between sessions.
  • Transition history — no UI to see "why did my weight change?" Verify whether this is still missing or was added during AI Coach work.
Not in day-one scope: AI voice coach, meal plans, double progression, 5/3/1, autoregulation, deload intelligence, AI profile engine. These are post-launch. Day one is: sign up, get workout, log it, see it improve.

Post-Launch What comes after — not launch-blocking

These improve the product but aren't required to ship. They're ordered by dependency — each one needs the previous to be stable first.

Next (after launch feedback)
  • Double progression — rep range 8–12, hit top → add weight → drop to bottom. Triggered by RIR at top set.
  • Transition: linear → double — stall detection auto-switches the user, AI explains the change.
  • Rule engine UI — settings to pick rule script per exercise group, exercise detail shows current prescription + estimated 1RM.
Later (more data needed)
  • Percentage-based (5/3/1 variant) — training max from history, week percentages, AMRAP set, deload every 4th week.
  • Recovery & deload intelligence — detect overreaching, missed sessions, declining performance. Auto-trigger deload.
  • Advanced autoregulation — per-user RIR calibration, volume landmarks (MRV/MAV/MEV), weak-point detection.
AI features (any timeline): AI coach chat is already in the app. Voice input during workout, TTS output, AI profile engine, and meal plan generation are all separate work items — not on the critical path for launch. Voice is push-to-talk only, never always-on.
Process How this stays current

This page is the source of truth. It gets updated when state changes — not on a schedule, not "when we get around to it."

  • When something ships: move it from "missing" to "shipped" here, same session.
  • When something gets blocked: mark it and say why. Don't leave it ambiguous.
  • When priorities shift: update the gap list. The old TODO.md was a graveyard of completed items that never got marked done — this replaces that pattern.
  • Phases are a planning tool, not a commitment. "Post-launch" items have no dates. They happen when the launch track is stable and there's capacity.
  • This page is rendered from backend/roadmap.html. To update it, edit that file and redeploy the backend.
