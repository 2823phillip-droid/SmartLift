SmartLift login/settings debugging — resumption note
=====================================================

What failed last night
----------------------
Login was aborting with `Fetch is aborted`, and Settings still wasn’t loading.

Key finding that changed the plan
----------------------------------
`phillipwalters.local` and `aiserver.local` do not reliably resolve on this network:
- `aiserver.local` returned NXDOMAIN
- `phillipwalters.local` resolves to the MacBook itself, not the Linux backend

So the yacht-realistic path is the raw LAN IP with iOS local-network permission.

What I changed in the frontend source (already on Linux, ready to rsync)
------------------------------------------------------------------------
- `src/api.ts`: request default/base/fallback = `http://192.168.1.111:8000/api`
- `src/api.ts`: raised critical request timeouts from 4s/3.5s to 10s/12s
- `src/pages/SettingsScreen.tsx`: placeholder/error text keeps the IP consistent

What I changed on the MacBook iOS project (needs verification)
---------------------------------------------------------------
- `frontend/ios/App/App/Info.plist`: added `NSLocalNetworkUsageDescription`
- `.env` should be set to `VITE_API_BASE=http://192.168.1.111:8000/api`
